# Chrome 擴充套件規劃書：截圖 → PIRLS 題組 → PaGamO

> 版本：草案 v0.2（2026-11-07）
> v0.2 依阿凱老師決定改版：**① 只做本機「開發人員模式」版本，用 ZIP 分享，不上 Chrome 線上應用程式商店；② 每位老師自備免費 Gemini API 金鑰，不再使用網站後端的額度。**
> 範圍：規劃階段，尚未開始寫程式。標「未確認」的項目要實地查證後才能定案。

## 一句話結論

擴充套件改成**自己就能完整運作的小工具**：截圖 → 用老師自己的 Gemini 金鑰出題 → 在擴充套件裡檢查、修改題目 → 產生 PaGamO 檔案並自動放進 PaGamO 批量上傳頁。**完全不經過網站後端**，也不占用學校這邊的 Gemini 額度。

> 比喻：以前是「全校共用一間廚房」，現在是發給每位老師一台「自己的電鍋」（擴充套件）和「自己的米」（金鑰）。誰煮幾次都不影響別人，學校廚房也不用排隊。

## 二、老師的使用流程

**第一次使用（約 5 分鐘）**
1. 下載 ZIP → 解壓到固定位置（建議 `D:\PIRLS擴充套件`，**之後不要搬動**）。
2. Chrome 網址列輸入 `chrome://extensions` → 打開右上「開發人員模式」→「載入未封裝項目」→ 選剛剛的資料夾。
3. 擴充套件自動打開「設定精靈」：點連結到 Google AI Studio 申請免費金鑰 → 貼上 → 按「測試」。測試會實際查詢這把金鑰能用哪些模型，綠燈才算完成。

**日常使用**
1. 在任何網頁（電子書、PDF、新聞、學習單）按工具列圖示或 `Alt+Shift+P`，框選要出題的段落，可連續框好幾張。
2. 選「8 題／10 題」「中文／英文」→ 按「開始出題」。
3. 開啟擴充套件的「工作台」分頁：左邊是截圖，右邊是 AI 整理的文章與題目，**老師逐題檢查、可直接修改**。
4. 按「🚀 送到 PaGamO（題組版／一般版）」→ 自動打開 PaGamO 批量上傳頁 → 擴充套件把檔案放進上傳欄位，核對平台辨識的列數與題數相符 → 框出確認鈕給老師按。
5. 加碼：網頁上**反白文字 → 右鍵「用這段文字出 PIRLS 題組」**，不用截圖。

PaGamO 自動放檔失敗時（例如 PaGamO 改版），工作台一樣可以「下載 xlsx」讓老師自己拖進去，不會整個不能用。

## 三、架構

```
任何網頁 ──截圖／反白──▶ 框選畫面（擴充套件）
                              │
                              ▼
               工作台分頁（擴充套件自己的頁面）
                 ├ 呼叫 Gemini（老師自己的金鑰）→ 文章＋題目
                 ├ 老師檢查、修改
                 └ 產生 PaGamO xlsx（內建 SheetJS＋官方範本前十列）
                              │ chrome.storage.local 暫存（3 分鐘有效、用完即刪）
                              ▼
               PaGamO 批量上傳頁（老師自己已登入）
                 └ 內容腳本：放入檔案 → 等預覽 → 核對列數 → 框出確認鈕
```

### 檔案規劃（放在本 repo 的 `extension/` 資料夾）

| 檔案 | 用途 |
|---|---|
| `manifest.json` | Manifest V3 設定 |
| `background.js` | 截圖、右鍵選單、快捷鍵、分頁之間傳話 |
| `capture/` | 框選畫面（暗色遮罩＋拖曳框） |
| `workbench/` | 工作台：出題、檢查、修改、匯出 |
| `options/` | 設定精靈：金鑰、模型、冊／章名稱 |
| `content/pagamo.js` | 在 PaGamO 批量上傳頁放檔、核對 |
| `lib/gemini.js` | 呼叫 Gemini、檢查回答格式 |
| `lib/prompt.js` | 出題提示詞（從 `functions/src/flows/` 同步） |
| `lib/pagamo.js` | 產生 PaGamO 檔案（移植自 `src/lib/buildPaGamOWorkbook.ts`） |
| `vendor/xlsx.full.min.js` | SheetJS，**放在套件裡**（Manifest V3 不允許從網路載入程式） |
| `lib/pagamoTemplates.json` | 從 `src/lib/pagamoTemplates.json` 同步 |

**不用打包工具**：純 JavaScript，解壓就能用，老師或其他資訊老師也看得懂、改得動。

### 一份正本，避免兩邊各改各的

提示詞和 PaGamO 範本現在在網站，擴充套件會各複製一份。為了不讓兩邊越改越不一樣：
- 新增 `tools/sync-extension.cjs`：把提示詞、`pagamoTemplates.json` 複製進 `extension/`。
- 擴充 `tools/test-platform-exports.cjs`：同一份題目分別用網站版和擴充套件版產生 PaGamO 檔案，**兩份內容必須完全一樣**，否則測試失敗。

### 呼叫 Gemini 的細節

- 用 Gemini REST API `generateContent`：圖片以 base64 內嵌，指定回答必須是 JSON 並附上固定格式（題目、四個選項、正解、解析、PIRLS 層次）。
- 回來後再檢查一次：題數是否正確、四層次分配是否正確、每題剛好 4 個選項。不符合就自動重試一次，再不行才提示老師。
- **模型不寫死**：設定精靈用 ListModels 查這把金鑰能用的模型，依偏好順序自動選（網站後端目前用 `gemini-2.5-flash`，文字辨識效果較好），老師也能手動改。實作當天再查一次可用清單（模型會陸續停用）。
- 圖片送出前轉 JPEG、長邊壓到約 2000px，加快速度、減少額度消耗。

### 權限（越少越好）

`activeTab`、`storage`、`contextMenus`、`scripting`；網址權限只列 `generativelanguage.googleapis.com` 與 PaGamO 網域。**不要求「讀取所有網站」**，**絕不經手 PaGamO 帳號密碼**。

## 四、金鑰安全：「在本機就沒有資安問題」大致對，但有 4 個小提醒

結論：老師用自己的金鑰、存在自己電腦，**比把金鑰放在公開網站安全得多**。不過還是有幾件事要在說明書寫清楚：

1. **金鑰存在電腦裡，不在 ZIP 裡**
   金鑰存在 Chrome 的擴充套件儲存區（`chrome.storage.local`，不用會跨電腦同步的 `sync`）。所以老師把資料夾壓成 ZIP 分享給別人時，**不會把自己的金鑰送出去**。
   > 比喻：鑰匙放在自己口袋，不是貼在要借給別人的書包上。

2. **共用電腦要小心**
   教室或辦公室共用電腦、同一個 Chrome 使用者，下一位使用者就能用到這把金鑰。設定頁提供「清除金鑰」按鈕，說明書提醒共用電腦用完要清除。

3. **申請時把金鑰限定只能用 Gemini**
   在 Google AI Studio／Cloud 主控台把金鑰的 API 限制設成「只允許 Generative Language API」。萬一外流，也不能拿去用其他付費服務。（擴充套件不是一般網站，原本用來鎖網域的「網站限制」不適用，所以改用「API 限制」。）

4. **免費方案的資料使用**
   依 Google 對免費方案的條款，送進免費 Gemini API 的內容可能被 Google 用來改進產品。課本、新聞截圖通常沒問題，但**不要截有學生姓名、成績等個資的畫面**。說明書與設定精靈都要寫這一句。

另外：免費金鑰有 Google 訂的「每分鐘／每天」次數上限，數字會變動（未確認，不寫死）；超過時擴充套件要顯示中文說明，請老師稍後再試。

## 五、ZIP＋開發人員模式的注意事項（依技能 `chrome-ext-unpacked-id-key-trap`）

- **ID 跟著資料夾位置走**：老師把資料夾搬家，Chrome 會當成另一個新的擴充套件，**金鑰與設定會全部消失**。說明書強調「解壓到固定位置、不要搬」。
- **更新方法**：下載新版 ZIP → **解壓覆蓋到同一個資料夾** → 到 `chrome://extensions` 按 ⟳。同一個位置就保留金鑰與設定。
- **manifest 不加 `key` 欄位**（加了會讓 Chrome 重開後擴充套件消失）。這個擴充套件不需要固定 ID，所以完全不用加。
- **新版本提醒**：擴充套件每天檢查一次 GitHub 上的版本號，有新版時在工作台顯示「有新版本，點這裡下載」。
- **驗收一定包含「關掉 Chrome 再打開」**，確認擴充套件還在、金鑰還在。
- 學校電腦若被網域政策管理，**可能不允許開發人員模式**（未確認）→ 第 1 階段找一台學校電腦實測。

## 六之一、第 0 階段偵察結果：PaGamO 頁面速查表（2026-11-07 實測）

用內建瀏覽器登入阿凱老師的 PaGamO 帳號（桃園市_PaGamO素養學習）實地查看。**全程沒有按「上傳」，沒有寫入任何題目。**

| 項目 | 實測結果 |
|---|---|
| 教師後台首頁 | `https://www.pagamo.org/api/teacher_console/home` |
| 個人題庫（題目總覽） | `/api/teacher_console/questions/overview` |
| **批量上傳頁** | **`/api/teacher_console/questions/add_questions/batch`**（可直接開這個網址，不用一層層點選單） |
| 題庫架構管理 | `/api/teacher_console/questions/structure_management` |
| 頁面技術 | React＋Ant Design，**沒有 iframe** |
| 題型選擇 | 單選按鈕「選擇題／是非題／填充題／題組」（`label.ant-radio-wrapper`），預設「選擇題」；點「題組」後範例檔連結自動換成題組版 |
| 檔案欄位 | `input[type=file]`，`accept=.xlsx,.png,.jpg,.jpeg,.mp3,.zip`、可多選，非 zip 檔單檔上限 **5 MB** |
| 送出按鈕 | `button[type=submit]`，文字「上 傳」 |
| 官方範本 | 仍是 `v5` 版，頁面標示「最近更新時間：2025/02」；下載後 SHA-256 與專案 `pagamoTemplates.json` **完全相同**，格式沒變 |

**三個關鍵發現：**

1. **選檔案不會馬上上傳**
   PaGamO 的上傳元件在選檔時只「記住檔案」（`customRequest` 直接回報成功、不發網路請求），真正送出要等按「上 傳」。
   > 比喻：像把作業放進老師桌上的籃子，還沒交出去，按「上傳」才是真的交件。
   所以擴充套件可以**安全地先放好檔案、選好題型，再讓老師自己按「上 傳」**。

2. **程式放檔已實測成功**
   用 `DataTransfer` 把一個假的測試檔放進檔案欄位並觸發 `change`：頁面正確列出檔名，「上 傳」按鈕變成可按，期間**沒有任何網路請求**。測完重新整理頁面就清掉了。

3. **Excel 的「科目／冊次／章節」三欄會直接變成題庫分類**
   9 月實測上傳的題目，在題目總覽顯示為「閱讀素養題組 > 資訊冊 > 資訊章」，在題庫架構管理也多了「閱讀素養題組」科目。可見上傳時 PaGamO 會依名稱自動歸類（沒有的分類應該會自動建立，推論自既有資料，未另外實測）。
   **建議**：設定頁讓老師自訂三欄，預設「科目＝閱讀素養題組、冊次＝學期（例：115上）、章節＝文章標題」，每篇文章自成一章，派作業時一眼找到。

**仍未確認（第 2 階段實際上傳時一併驗證，需老師同意寫入題庫）：**
- 按「上 傳」後的結果畫面長什麼樣（辨識幾列、錯誤訊息出現在哪），這決定「核對列數」怎麼做。
- 由程式按「上 傳」是否被接受（目前規劃不需要，由老師自己按）。
